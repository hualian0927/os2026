## 四、实验内容与实现

### 前序依赖迁移与双向Trap

**负责人：** 李华濂（2412351）。

#### 模块功能描述

迁移的主要接口包括page_init、完整Best-Fit、page_insert/page_remove、必要的基础创建/切换/调度，以及RESTORE_ALL和__alltraps。迁移来源保留在代码注释中，没有覆盖Lab5新增的alloc_proc、kernel_thread、copy_mm等占位。既有调度和switch实现保留2312115的来源，不将迁移记作重新原创。

page_init从设备树getter取得范围，检查零值、溢出、可管理上界及描述符空间。先设置虚实偏移，再用内核end安排页对齐的Page数组。npage是管理上界的物理页号，npage-nbase才是数组元素个数；先保留全部描述符，再将内核及描述符之后的完整页面交给分配器。Best-Fit保持块头地址有序、property为连续页数、nr_free为页数，选择最小足够块，同大小选择低地址。

物理页alloc/free/count接口继续使用原local_intr_save/restore：记录当前SIE，必要时关中断，退出时按保存状态恢复。每层嵌套标志独立、按逆序恢复；这只是当前hart的保护，不等于多核锁。

目标Trap frame共288字节，由32个通用寄存器槽和status、epc、tval、cause组成。U态进入时交换sp与sscratch，切到可信内核栈并保存用户sp；S态进入时继续使用原内核栈。__alltraps将保存后的帧sp放入a0，调用trap(tf)。恢复时先采用C处理后的status/epc，再恢复通用寄存器，最后恢复sp，避免读帧过程中丢失寻址基准。

返回U态时sscratch指向可信内核栈顶，返回S态时为0。sret按SPP决定返回级别，以SPIE恢复SIE并更新相关状态，不能要求整个sstatus逐位相等。tval/cause用于诊断，不机械写回CSR。当前检查覆盖单hart、有效栈和受控Trap，不扩展任意嵌套或损坏现场容错。

迁移时按目标接口核对而不是整文件替换。当前QEMU/OpenSBI下，原device loader不能提供预期下一阶段入口，分页切换又需要低地址取指映射，因此仅适配正式qemu/debug加载和entry.S。相关失败与修复日志保留在迁移材料中；原评分加载脚本未改动。

本轮审查发现时钟迁移遗漏：原处理只重装定时器和计数，没有设置need_resched。原spin用户程序的子进程一直自旋，后续必须让父进程重新运行才能kill它。我先用真实U态自旋和硬件时钟保留失败，实际打印100 ticks后仍超时；再只增加current非空时的need_resched通知，仍由既有Trap出口在U态返回时调度。相同测试修复后在tick 1到达调度观察入口。没有代写真实进程切换或kill业务。

### 功能模块一：用户态系统调用

**负责人：** 李华濂（2412351）。

#### 模块功能描述

**需要实现/修改的函数：**

```c
void exception_handler(struct trapframe *tf);
void syscall(void);
static int sys_exit(uint64_t arg[]);
static int sys_fork(uint64_t arg[]);
static int sys_wait(uint64_t arg[]);
static int sys_exec(uint64_t arg[]);
static int sys_yield(uint64_t arg[]);
static int sys_kill(uint64_t arg[]);
static int sys_getpid(uint64_t arg[]);
static int sys_putc(uint64_t arg[]);
static int sys_pgdir(uint64_t arg[]);
```

**功能说明：** 本模块负责用户请求进入、参数适配与结果返回。它调用后续do_*接口，不负责复制进程、装载ELF或回收退出资源。当前链路如下：

```text
用户封装：a0=编号，a1～a5=参数
 → ecall → __alltraps → trap(tf)
 → exception_handler：识别CAUSE_USER_ECALL，EPC先加4
 → syscall：检查编号和空项，提取5个参数
 → sys_* → 对应do_*或控制台接口
 → 有符号结果写回帧内a0 → 恢复处理后的帧 → sret
```

本实验使用a0而非a7存放调用号。分发表长度32，实际支持1、2、3、4、10、12、18、30、31；编号在范围内但表项为空也必须拒绝。先检查完整64位编号，再索引，避免截断后的大编号误命中有效调用。非法编号和入口参数错误返回-E_INVAL，后端错误原样传回。

| 适配函数 | 实际转发与关键约定 |
|---|---|
| sys_exit | do_exit(int code)，检查整数范围；成功不返回由后端保证 |
| sys_fork | do_fork(0, tf->gpr.sp, tf)，普通复制；父PID、子帧a0=0由后端区分 |
| sys_wait | do_wait(pid, store)，允许NULL，非NULL检查4字节可写范围 |
| sys_exec | do_execve(name, len, binary, size)，依次取a1～a4；检查输入可读范围，不解析ELF |
| sys_yield | do_yield()，后端负责设置重新调度状态 |
| sys_kill | do_kill(pid)，后端负责目标状态、唤醒和退出意图 |
| sys_getpid | 返回实际current->pid，不强制要求mm非空 |
| sys_putc | 调用实际cputchar后返回0 |
| sys_pgdir | 调用print_pgdir后返回0；目标框架尚缺该函数定义，真实输出未完成 |

PID、退出码和字符目标接口接收有符号int，因此先检查64位值是否在其范围内；指针和长度保持64位。用户范围检查复用真实user_mem_check，但显式排除mm为空时退入内核地址检查的情况。exec名称长度为0时不读取名称字节，最终命名和ELF规则交给后端。后端仍须在实际复制、睡眠和回收阶段完成最终检查，不能先回收子进程再发现退出码写不回去。

trap临时令current->tf指向本次帧，正常返回后恢复原指针；这不会撤销已经写入帧内的返回值或入口。EPC必须在调用后端前推进，否则exec更新的新入口会被错误再加4。分发层只写返回a0，不固定返回U态，不丢弃后端对有效帧的合法修改。

## 六、实验总结与收获

### 对操作系统的理解

| 本实验知识点 | 对应OS原理及关系 |
|---|---|
| U/S切换、sscratch、可信内核栈 | 对应特权隔离与异常处理。硬件记录部分CSR，软件保存通用寄存器，二者共同构成可恢复现场 |
| syscall/sys_*与do_*分层 | 对应系统调用机制与内核服务。入口解决ABI和边界，后端处理具体业务及资源状态，不能混为一层 |
| 用户指针与VMA检查 | 对应地址空间保护。检查合法区间不等于数据永远驻留，也不能替代实际复制时的资源协调 |
| 引用计数与地址空间生命周期 | 对应共享资源和回收。后续fork/exec/wait/exit必须统一页和mm的所有权，本阶段只固定入口契约 |
| 时钟通知与Trap出口调度 | 对应可抢占用户执行。仅有周期性中断不代表一定会调度，还需要设置请求并到达允许切换的位置 |
| 局部关中断 | 对应单核临界区保护。恢复的是原状态，不能把它当成多核互斥锁 |

OS原理中重要但本人当前阶段没有实现或验证的内容包括：完整用户进程生命周期、多核同步、信号与完整权限模型、可恢复的用户内存复制、按需分页、换页及完整COW。页表框架冲突和缺失打印函数也需继续解决，不能把“暂时未覆盖”写成“不需要”。
