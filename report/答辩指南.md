## 三、用两条链讲清楚整体思路

第一条是资源准备链：

```text
物理页分配 → kmalloc分配PCB → 分配线程内核栈
          → 构造trapframe/context → 分配PID、挂链表 → RUNNABLE
```

第二条是执行链：

```text
kern_init
  → proc_init
      → 当前现场包装为idleproc，current=idleproc
      → kernel_thread(init_main, ...)
          → do_fork → copy_thread → wakeup_proc
  → cpu_idle
      → schedule → proc_run → switch_to
          → forkret → forkrets → __trapret → sret
              → kernel_thread_entry → init_main(arg)
```

这两条链回答不同问题：第一条让线程“存在并准备好”，第二条让它“真正得到CPU”。创建线程不会自动在创建点立即执行线程函数。

## 四、模块一怎样讲：page_insert/page_remove

### 4.1 三个对象必须一致

PTE告诉硬件“地址映射到哪里”；Page.ref记录映射引用；TLB可能缓存旧翻译。修改映射必须同时处理三者，否则会出现PTE更新了但还访问旧页，或页仍被使用却已回收。

核心代码在 `pmm.c:334`：

```c
pte_t *ptep = get_pte(pgdir, la, 1);
if (ptep == NULL) return -E_NO_MEM;
if (!(*ptep & PTE_V) || pte2page(*ptep) != page) {
    page_ref_inc(page);
    page_remove_pte(pgdir, la, ptep);
}
*ptep = pte_create(page2ppn(page), perm);
tlb_invalidate(pgdir, la);
```

逐句解释：先保证有槽位；没有资源先返回，不动数据页ref。新映射或替换其他页时给新页加引用，并撤销旧映射。同页重映射跳过这一步，所以不会多算引用，也不会先释放当前页。最后写新PTE、失效本地址TLB。

`pte_create()`内部补PTE_V；不能只看调用行就以为此处忘了有效位。

### 4.2 老师常追问的分支

| 情形 | 结果 |
|---|---|
| 原地址未映射 | 新页ref加1，写入PTE |
| 原地址已经映射同一页 | 只改权限，ref净变化0 |
| 原地址映射另一页 | 新页加1，旧页减1；旧页归0才释放 |
| 多个地址共享旧页 | 只减当前这一份引用，其余映射继续有效 |
| 删除不存在的地址 | get_pte传create=0，安全返回 |
| 重复删除 | PTE已清零，不会再次释放 |
| 中间表第二次分配失败 | 只释放本次新建的第一张表，恢复原父项 |

`page_remove_pte()`在310行：清PTE → 失效TLB → 减引用 → 必要时free_page。正常删除不会回收空中间表；这与“创建失败时回滚本次表页”是两个不同约定。

### 4.3 可以在纸上演算

A刚分配时ref=0；X映射A后1；Y也映射A后2；X换成B后A为1、B为1；删Y才回收A；删X才回收B。同页更新任意多次都不应该把ref越加越大。

## 五、模块二怎样讲：创建线程

### 5.1 六个函数分工

| 函数与行号（proc.c） | 一句话说明 |
|---|---|
| alloc_proc：224 | 分配干净PCB，字段设安全初值 |
| proc_init：333 | 包装idle并创建init |
| kernel_thread：319 | 把fn/arg装进临时trapframe |
| do_fork：270 | 分配栈、复制现场、分配PID、登记并唤醒 |
| copy_thread：249 | 把帧放到新栈，设首次返回地址和栈指针 |
| copy_mm：263 | 当前只支持共享内核空间，mm为空，不复制用户空间 |

`do_fork()`失败处理按取得资源的逆序进行：还没拿到栈就释放PCB；已经拿到栈则先put_kstack再kfree。PID和链表登记在准备完成后执行，避免把半成品交给调度器。

### 5.2 idle和init有什么区别

idle的PID是0，不是fork创建，复用正在执行的启动栈。current先指向idle，need_resched设1，为首次调度做准备。idle不挂普通proc_list，所以没有候选时调度器显式回退到它。

init通过正常kernel_thread流程创建，首个正常PID应为1，父线程为idle，有新分配的内核栈及人工构造的首次现场。

### 5.3 首次运行是最重要的追问

在 `copy_thread()`里重点指出：

```c
proc->tf = (struct trapframe *)(proc->kstack + KSTACKSIZE) - 1;
*proc->tf = *tf;
proc->tf->gpr.a0 = 0;
proc->tf->gpr.sp = (esp == 0) ? (uintptr_t)proc->tf : esp;
proc->context.ra = (uintptr_t)forkret;
proc->context.sp = (uintptr_t)proc->tf;
```

栈向低地址增长，帧先放在新栈顶。copy_thread把调用者局部tf复制下来，因此kernel_thread返回后它仍有效。

第一次切入分成两次“跳转决定”：switch_to的ret看context.ra，先到forkret；__trapret的sret看trapframe.epc，再到kernel_thread_entry。这个区分一定要讲清。

`kernel_thread()`还设置：s0=函数，s1=参数，epc=入口；SPP=1意味着返回S态，SPIE=1使sret返回后允许S态中断，SIE在恢复过程保持关闭。入口汇编 `move a0,s1; jalr s0` 才真正调用fn(arg)。

## 六、模块三怎样讲：调度和切换

### 6.1 schedule决定选谁，switch_to决定怎么换

`schedule()`从当前线程后一个节点开始，绕过链表头，找第一个PROC_RUNNABLE；从idle进入时从链表头之后找。循环一圈仍没有可运行对象，就选择idle。选中对象runs加1，目标不同才proc_run。

当前是链表循环扫描，单次最坏O(N)。没有优先级、时间片；头插登记也意味着不能承诺严格按创建先后运行。

`proc_run()`先更新current，再写satp、刷TLB，最后switch_to。中间关中断是为了避免“current已经换了，实际寄存器还没换”的状态被当前hart中断观察到。

### 6.2 satp怎么写

```text
satp = (8ULL << 60) | (页表根物理地址 >> 12)
```

高4位MODE为8表示Sv39，低位PPN是根表物理页号；本实现ASID为0。一定是物理地址，不是boot_pgdir_va。当前所有内核线程用同一内核根，但保留了统一切换接口。写完satp后另做sfence.vma，不能假定写CSR自动刷新所有旧翻译。

### 6.3 为什么switch_to只有14个寄存器

`struct context`位于 `proc.h:18`，顺序是ra、sp、s0～s11。`switch.S:8`开始用sd保存，23行开始用ld恢复，最后ret。偏移0、8、16……104对应14个uintptr_t。

这是在函数调用边界主动切换：调用者负责a/t等易失寄存器，被调用者保存寄存器由切换函数保存。异步Trap可打断任意指令，必须用更完整的trapframe。

### 6.4 旧线程什么时候从switch_to返回

旧线程切走时，自己的ra/sp已经保存。以后别的线程把它切回来，才恢复那组ra/sp，从原来switch_to调用后继续。因此“执行了switch_to”不等于旧线程立刻执行下一行。每个线程会在自己恢复执行后完成对应的local_intr_restore。

## 七、VMA、Page、PTE容易混淆的地方

| 名称 | 保存什么 | 不能混成什么 |
|---|---|---|
| Page | 一页物理内存的元数据、引用和分配属性 | 不是物理页数据本身 |
| PTE | 物理页号、有效位和访问权限 | 不是VMA区间 |
| VMA | [start,end)虚拟区间及读写执行属性 | 不会自动分配每个数据页 |
| mm_struct | 一组VMA、缓存、页表指针等地址空间管理信息 | 当前内核线程mm仍为NULL |
| context | 线程主动切换所需的14个寄存器 | 不是完整Trap现场 |
| trapframe | 通用寄存器及状态/返回PC等Trap信息 | 不是PCB本身 |

`find_vma()`实际采用 `start <= addr < end`，虽然其旧注释写了包含右端，答辩应以代码和结构约定为准。`insert_vma_struct()`按地址组织且检查重叠。框架已存在不代表已经实现用户态内存管理。

## 八、Challenge快速回答

**1. local_intr_save为什么不是简单关中断？**

还要保存进入前的SIE。如果原来关闭，离开时不能误开。save读sstatus.SIE，原开才清位；restore仅在保存值为1时开。代码在 `sync.h:8` 和16行，底层intr_enable/disable在driver/intr.c。

**2. 嵌套会不会提前开？**

每层独立标志、逆序恢复就不会。外层读1并关，内层读0，内层恢复不打开，外层最后打开。不能共用一个flag，也不能在临界区擅自开中断。

**3. 关中断能防多核并发吗？**

不能，只影响当前hart；其他核仍可访问共享数据。同步异常也不会因此被屏蔽。

**4. get_pte为什么有两段相似代码？**

Sv39三级，根已存在，还要按需创建两张下级表。每层都是“有效性检查—分配—清零—父项连接”，所以重复。Sv32需一次下级创建，Sv48需三次。

**5. 三种模式怎么记？**

Sv32：2级，10+10+12，4字节PTE；Sv39：3级，9+9+9+12，8字节PTE；Sv48：4级，四个9再加12，8字节PTE。每张基本页表都是4KiB。

**6. 查找和创建该不该拆？**

当前create参数可复用遍历，简单但有分配副作用及回滚复杂度。复杂并发、大页或可阻塞分配场景可拆walk/ensure，同时处理两次遍历之间的变化。没有必要只为思考题重写当前API。

## 九、其他高频追问

**7. 有时钟中断为什么不算抢占调度？**

当前 `trap.c:115`的handler只安排下次时钟、计数和打印，没有扣减时间片、设调度需求并在安全出口切换；线程要主动schedule才让出CPU。

**8. RUNNABLE是不是说明它还没运行？**

不一定。本实现把就绪与运行合在RUNNABLE，current指向的才是正在运行的对象。

**9. 共享页表为什么还要独立栈？**

每个线程的局部变量、返回地址、调用链和Trap帧需要分别保存；共享地址空间不代表共享同一份执行进度。

**10. TLB是什么，sfence.vma在刷什么？**

TLB缓存虚拟地址到物理地址及权限的翻译。改PTE后必须防止旧翻译继续使用。它不是数据缓存，当前指令也不完成其他hart的TLB shootdown。

**11. get_pte按需建表算按需分页吗？**

不算。这里按需申请管理结构“页表页”，没有在进程缺页时加载或分配目标数据页。

**12. do_fork就等于Unix fork吗？**

不是。当前它是线程创建公共路径，copy_mm不复制用户空间，也没有用户进程、写时复制等完整语义。

**13. kernel_thread返回0是不是说明子线程已经跑了？**

不是，创建接口正常返回新PID；帧中a0=0是新现场的约定，真正执行还要等调度。此内核线程入口随后用s1覆盖a0传递arg。

**14. 线程函数返回会怎样？**

入口汇编随后调用do_exit；当前do_exit在 `proc.c:206`直接panic，不是正常回收。不能声称实现了退出、wait和僵尸回收。

**15. 软件页表检查通过，为什么真实读还失败？**

软件测试只证明它观察的PTE/ref关系。修前get_pte两级非叶子都带U位，违反Sv39的U/A/D保留规则，历史VA=0x4000读发生cause=13。本轮已改为ptd_create，并纠正原自检要求父项U=1的断言；Debian修后check_boot_pgdir已通过并进入init，原独立generated测试与完整矩阵仍需回归。

**16. 原有页表测试中的perm=0可以直接访存吗？**

不能一概而论。有效但RWX均为0的项在硬件意义上是指向下级表的项，不是普通数据叶子；W=1、R=0也属于非法组合。课程软件记账测试与硬件访存验收必须分清。

**17. 空页表什么时候回收？**

当前正常page_remove只撤销数据页叶子，中间表由调用者管理；插入失败则撤销本次新增的表。这两个策略不矛盾。

**18. spec和prompt分别是什么？**

Spec规定输入、前提、成功和失败后状态，例如同页ref不变、失败不影响旧映射；prompt把这些约束、文件边界和验证要求交给AI。测试据Spec观察状态，不是看到AI说完成就算完成。
