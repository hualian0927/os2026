## 5. 肖子昂＋杨昊冉：完整功能模块二——进程创建及初始化

主要填写位置：`kern/process/proc.c:221`的`LAB4 function2 YOUR CODE`区域。

| 函数 | 双人组共同完成的内容 |
|---|---|
| `alloc_proc()` | 分配PCB并初始化全部基础字段，保证失败可识别、未运行状态安全 |
| `proc_init()` | 初始化进程链表和哈希表，把当前启动执行现场登记为idleproc，设置current，创建并命名initproc |
| `kernel_thread()` | 构造临时Trap frame，安排函数入口、参数、返回特权级及中断状态，然后调用`do_fork()` |
| `do_fork()` | 串联PCB、内核栈、地址空间处理、现场复制、PID、链表登记和唤醒；失败时正确清理已取得的资源 |
| `copy_thread()` | 在新线程自己的内核栈上放置Trap frame，设置子线程返回值、sp，以及首次运行所需的context.ra和context.sp |
| `copy_mm()` | 按当前内核线程共享内核空间的范围实现接口；维持`mm == NULL`等约定，不提前实现用户地址空间复制 |

这部分同时负责讲清：idleproc复用现有执行流，initproc才是通过新建栈和人工现场启动的内核线程；`PROC_RUNNABLE`涵盖就绪与正在运行，不能自行引入不匹配的状态字段。

已有检查入口为`tools/test_lab4.c:test_lab4_process_create()`。除已有检查外，需要关注资源失败清理、PID和链表登记的一致性，不只判断initproc指针非空。

## 6. 肖子昂＋杨昊冉：完整功能模块三——调度与上下文切换

| 文件与占位 | 函数 | 负责行为 |
|---|---|---|
| `kern/process/proc.c:224`，`LAB4 function3` | `cpu_idle()` | 检测`need_resched`并触发调度 |
| 同上 | `proc_run()` | 在受保护区域内协调current、页表和上下文切换；避免切到自身时的不必要操作 |
| `kern/schedule/sched.c:13`，`LAB4 function3` | `schedule()` | 清调度请求，按链表次序选择可运行线程；处理遍历回绕、idle兜底及runs计数，调用`proc_run()` |
| `kern/process/switch.S:1`，`LAB4 function3` | `switch_to()` | 按`struct context`布局保存旧线程、恢复新线程的ra、sp、s0～s11，并转到目标执行位置 |

实际包内文件名为大写后缀`switch.S`；题目函数列表中的`switch.s`应以压缩包实际路径为准。

双人组负责将以下链路完整跑通并解释：

```text
cpu_idle → schedule → proc_run → switch_to
    → forkret → forkrets → __trapret
    → kernel_thread_entry → init_main
```

共同约定：

- `copy_thread()`构造的context必须与`switch_to()`恢复的寄存器偏移一致；这是双人组内部统一负责的接口。
- `proc->pgdir`保存页表根的物理地址，写`satp`时需要构造Sv39模式和物理页号，并按要求刷新TLB；题目已明确不能使用Sv32遗留的`lsatp()`。
- 关中断和恢复必须保持原SIE状态；A负责讲清原理，B负责自己调度路径中的正确使用，不能把挑战题归A理解成调度保护也由A代写。
- 本实验按给定调度点实现协作式切换；不额外增加时间片抢占、完整进程退出回收或用户态切换。
- 包内`do_exit()`已有`panic("process exit!!.")`占位式行为，线程入口返回后可能走到这里。需结合测试判断预期现象，不把它直接当作必须新增完整退出系统的要求。

现有调度测试`test_lab4_schedule()`会创建两个测试线程并主动多次调用`schedule()`，检查两者是否都获得执行；不能只用initproc打印一条消息代替多线程切换检查。
