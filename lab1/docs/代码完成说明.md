## 已完成的代码

| 文件 | 修改与用途 |
| --- | --- |
| `kern/init/entry.S` | 入口使用独立 `.text.kern_entry` 段；说明栈设置与尾跳转语义 |
| `tools/kernel.ld` | 优先保留入口段，并断言入口必须等于 `0x80200000`，不依赖目标文件排列顺序 |
| `kern/init/init.c` | 保留 `.bss` 清零、打印启动消息、无限循环，补充职责说明 |
| `libs/sbi.c` | 用绑定寄存器的扩展汇编正确描述 `a0/a1/a2/a7`，明确 `a0` 是输入/输出 |
| `libs/printfmt.c` | 用无符号取负处理负数绝对值，避免最小 64 位有符号整数的溢出 |
| `Makefile` | 适配本机 QEMU/OpenSBI 与 GDB；新增 `check` 入口 |
| `tools/boot.gdb` | 自动跟踪复位、固件、内核入口、栈初始化及进入格式化输出的过程 |
| `tools/check_lab1.py` | 自动启动 QEMU/GDB，检查结果并管理测试进程和日志 |
| `tools/grade.sh` | 原资源缺失脚本的本地替代，调用 `make check`，不输出课程分数 |
| `tests/console.c` | 独立输出测试内核，验证格式化内容与返回字符数，不覆盖正式 `kern_init` |

SBI 修正依据 [GCC 寄存器变量说明](https://gcc.gnu.org/onlinedocs/gcc/Local-Register-Variables.html) 和 [RISC-V SBI 旧版接口规范](https://github.com/riscv-non-isa/riscv-sbi-doc/blob/master/src/ext-legacy.adoc)：寄存器变量用于扩展汇编操作数；本项目使用的旧版 SBI 约定由固件保留 `a0` 之外的寄存器。

## 使用方式

```bash
conda activate os2026
cd /home/lhl/os2026/lab1
make grade    # 清理、重编译、运行本地自检
make qemu     # 正式最小内核：输出后无限循环
```

`make check` 使用现有构建并按依赖增量编译。测试用临时目录和独立 Unix socket，不占用手动调试的 TCP 1234 端口；完成或失败时关闭自身启动的 QEMU，保留日志到 `obj/check/`。

手动完成练习2时，两个终端分别运行 `make debug` 和 `make gdb`。在刚连接、PC 为 `0x1000` 的 GDB 中执行：

```gdb
source tools/boot.gdb
```

也可以逐条手动执行 [环境说明](环境配置.md) 中的命令。自动脚本会在检查完成后 `detach`，使正式内核继续打印消息。

## 实测结果

- `make grade` 清理后完整构建通过。
- 复位 PC：`0x1000`；单步抵达 OpenSBI：`0x80000000`；内核入口：`0x80200000`。
- `la` 完整执行后 `sp = bootstacktop = 0x80203000`，栈大小 8192 字节且满足 16 字节对齐。
- `tail` 后抵达 `kern_init = 0x8020000a`，`ra` 保持不变。
- 当前正式内核的 `edata == end`，清零区间长度为零，日志明确记录；不能把此结果描述为非空 `.bss` 清零测试。
- 正式内核打印 `(THU.CST) os is loading ...`。
- 独立测试内核分别以 `-O0` 和 `-O2` 构建并启动，验证 `%s/%d/%u/%x/%p/%c/%%/%08x/%lld/%llu`、64 位边界值及字符计数。
- 测试内核故意将入口目标文件放在链接列表最后，验证链接脚本仍保证正确入口。

主要日志：`obj/check/gdb-startup.log`、`obj/check/qemu.log`、`obj/check/console-O0.log`、`obj/check/console-O2.log`。`make clean` 会清除这些构建产物，正式报告所需证据应另存。
