## 三、修改和反馈迭代

1. **初始构建**：原始代码可以编译，但本机 loader 启动方式未把正确后续入口传给 OpenSBI。根据输出为零的下一入口，改用 `-kernel`，验证内核消息出现。
2. **调试器**：原 GDB 和尝试安装的普通 Conda GDB 不支持 RISC-V；改用多架构 GDB，验证能从复位地址跟踪。
3. **入口布局**：将入口独立成段并添加链接断言。自检把入口对象放在链接列表最后，仍成功启动。
4. **输出可靠性**：修正 SBI 汇编寄存器约束及最小有符号整数取负。分别以 O0、O2 构建独立测试内核，检查字符串和字符计数。
5. **报告证据**：2026-09-30 重新执行完整自检，将日志和符号布局固定保存至 `docs/evidence/2026-09-30/`，再根据实际结果完成报告。
