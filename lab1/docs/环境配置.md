## 调试器安装方式与重建

系统原有 GDB 和本次尝试的 Conda `gdb` 包均不支持 `riscv:rv64`，因此已移除后者，采用 Ubuntu 官方仓库的 `gdb-multiarch` 二进制包。该包解压到 `$CONDA_PREFIX/opt/gdb-multiarch`，`$CONDA_PREFIX/bin/gdb-multiarch` 是指向实际程序的符号链接。未全局安装软件，也未使用 sudo。

这是 **Conda 环境内的额外工具**，不由 Conda 包管理器管理；单独使用 `environment.yml` 不会重建它。以下命令适用于同类 Ubuntu 24.04 x86_64 主机（需要已有兼容的系统动态库）：

```bash
conda env create -f environment.yml
conda activate os2026
pkg_dir=$(mktemp -d)
(
    cd "$pkg_dir"
    apt-get download gdb-multiarch
    mkdir -p "$CONDA_PREFIX/opt/gdb-multiarch"
    dpkg-deb -x ./gdb-multiarch_*.deb "$CONDA_PREFIX/opt/gdb-multiarch"
)
ln -s ../opt/gdb-multiarch/usr/bin/gdb-multiarch "$CONDA_PREFIX/bin/gdb-multiarch"
gdb-multiarch --batch -ex 'set architecture riscv:rv64'
```

本次实际使用包：`gdb-multiarch_15.1-1ubuntu1~24.04.1_amd64.deb`。上述下载命令会获取仓库当时提供的版本。其他操作系统应采用对应平台的多架构 GDB；本文件不把整个系统工具链宣称为 Conda 可移植环境。

## Makefile 的两处兼容性调整

1. `qemu` 和 `debug` 目标以 `-kernel bin/ucore.img` 传入镜像。本机原来的 `-device loader,...` 只装入镜像，没有正确传递后续入口：OpenSBI 输出的 `Domain0 Next Address` 为零，未进入内核。修改后该值为 `0x80200000`，内核正常输出。
2. 调试器默认改为 `GDB ?= gdb-multiarch`，`gdb` 目标使用 `$(GDB)`。如果另一台机器有交叉调试器，可用 `make gdb GDB=riscv64-unknown-elf-gdb` 覆盖。

同时将 `debug`、`gdb` 声明为伪目标。以上是环境准备阶段的修改；后续按用户要求完成代码时，还修正了入口段布局、SBI 调用约束及整数格式化边界，见 [代码完成说明](代码完成说明.md)。

## 双终端调试

两个终端均先激活 `os2026` 并进入 `lab1`。

终端一：

```bash
make debug
```

终端二：

```bash
make gdb
```

GDB 内的基础流程（仅适用于一次新启动的 QEMU）：

```gdb
set pagination off
info registers pc
x/6i 0x1000
x/3i 0x80200000
si 5
info registers pc a0 a1 a2 t0
si
info registers pc
break *0x80200000
continue
x/3i $pc
info registers pc sp
si 2
info registers sp
p/x &bootstacktop
si
info registers pc
```

本机的 `la sp, bootstacktop` 展开成两条机器指令，因此用 `si 2` 验证完整效果；其他工具链应先看反汇编，再决定步数。GDB 退出前可用 `detach` 让内核继续执行，再在 QEMU 终端退出模拟器。
